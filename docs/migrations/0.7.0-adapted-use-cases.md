# Migrating v0.6.0 Typed Boundary Use Cases to v0.7.0 Adapted Use Cases

v0.7.0 replaces the v0.6.0 typed-boundary API with `adaptedUseCase`.

The core model is:

- `useCase<C>(name = "...") { ... }` remains the workflow-native DSL for callers that work with `UseCaseCommand`, `WorkflowError`, states, and events.
- `adaptedUseCase<I, E, O>(name = "...") { ... }` is the application-boundary DSL for callers that need public input, public errors, and public output.
- Public input is mapped into an internal `UseCaseCommand`.
- `WorkflowError` can be mapped to a boundary error type.
- Public output is projected from either the final state or an emitted event.
- The optional `name` is used for debug-level invocation logs. Keep it stable and free of user data.

## State Projection

Before:

```kotlin
val registerUser: ContextualTypedUseCase<RegisterUserCommand, ApplicationError, UserDto> =
  registerUserUseCase.toStateUseCase(
    inputMapper = ::RegisterUserWorkflowCommand,
    errorMapper = WorkflowError::toApplicationError,
    outputMapper = { state: RegisteredUserState -> state.user.toDto() },
  )
```

After:

```kotlin
val registerUser: AdaptedUseCase<RegisterUserCommand, ApplicationError, UserDto> =
  adaptedUseCase(
    name = "RegisterUser",
    errors = WorkflowError::toApplicationError,
  ) {
    input(::RegisterUserWorkflowCommand)
    workflow {
      startWith { command -> command.toValidatedState() }
      then(HashPasswordStep(passwordHasher))
      then(PersistUserStep(userRepository, userIdGenerator))
    }
    result(state<RegisteredUserState>()) { state -> state.user.toDto() }
  }
```

## Event Projection

Before:

```kotlin
val registerUserEvent: ContextualTypedUseCase<RegisterUserCommand, ApplicationError, UserRegisteredEvent> =
  registerUserUseCase.toEventUseCase(
    inputMapper = ::RegisterUserWorkflowCommand,
    errorMapper = WorkflowError::toApplicationError,
    outputMapper = { event: UserRegisteredEvent -> event },
  )
```

After:

```kotlin
val registerUserEvent: AdaptedUseCase<RegisterUserCommand, ApplicationError, UserRegisteredEvent> =
  adaptedUseCase(
    name = "RegisterUser",
    errors = WorkflowError::toApplicationError,
  ) {
    input(::RegisterUserWorkflowCommand)
    workflow {
      startWith { command -> command.toValidatedState() }
      then(HashPasswordStep(passwordHasher))
      then(PersistUserStep(userRepository, userIdGenerator))
    }
    result(event<UserRegisteredEvent>()) { event -> event }
  }
```

## Raw Workflow Errors

Before:

```kotlin
val registerUser: ContextualTypedUseCase<RegisterUserCommand, WorkflowError, UserDto> =
  registerUserUseCase.toStateUseCase(
    inputMapper = ::RegisterUserWorkflowCommand,
    outputMapper = { state: RegisteredUserState -> state.user.toDto() },
  )
```

After:

```kotlin
val registerUser: AdaptedUseCase<RegisterUserCommand, WorkflowError, UserDto> =
  adaptedUseCase(name = "RegisterUser") {
    input(::RegisterUserWorkflowCommand)
    workflow {
      startWith { command -> command.toValidatedState() }
      then(HashPasswordStep(passwordHasher))
      then(PersistUserStep(userRepository, userIdGenerator))
    }
    result(state<RegisteredUserState>()) { state -> state.user.toDto() }
  }
```

Omit `errors = ...` only when the adapted use case's error type is `WorkflowError`.

## Direct UseCase Implementations

If you directly subclass `UseCase`, move custom behavior into `executeUseCase`.
The public execution methods now wrap that protected hook so invocation logging is applied consistently.

Before:

```kotlin
class RegisterUserUseCase : UseCase<RegisterUserCommand>() {
  override suspend fun execute(command: RegisterUserCommand): Either<WorkflowError, UseCaseEvents> {
    // Custom implementation
  }
}
```

After:

```kotlin
class RegisterUserUseCase : UseCase<RegisterUserCommand>("RegisterUser") {
  override suspend fun executeUseCase(
    command: RegisterUserCommand,
    context: WorkflowContext
  ): Either<WorkflowError, UseCaseResult<WorkflowState>> {
    // Custom implementation
  }
}
```

## Invocation

Adapted use cases are invoked directly:

```kotlin
val result = registerUser(command)
```

If the boundary has request metadata, pass an initial `WorkflowContext`:

```kotlin
val result =
  registerUser(
    command,
    WorkflowContext().addData(WorkflowContext.CORRELATION_ID, correlationId),
  )
```
