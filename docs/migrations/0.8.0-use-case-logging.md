# Migrating to v0.8.0 Use Case Logging

v0.8.0 adds configurable, type-safe debug logging for `useCase` operations.

Existing `useCase { ... }` definitions do not need to change unless you want to add explicit success or failure fields. The default logs remain safe: command input, workflow state, event payloads, projected output, and error payloads are not logged unless you explicitly project fields.

## What Changed

- `useCaseLoggingGlobalConfig { ... }` configures process-wide formatting at application startup.
- `logging { ... }` inside `useCase { ... }` adds explicit fields to the finish log.
- Success logging can project from `state<T>()` or `event<T>()`.
- Failure logging is typed to the use case error type `E`.
- Logging projection failures do not change the use case result.
- Built-in log field names are reserved: `name`, `outcome`, `durationMs`, `events`, and `workflows`.

## Safe Defaults

By default, a finished use case emits operational metadata only:

```text
UseCase invocation finished name=RegisterUser outcome=success durationMs=12 events=1 workflows=2
```

That default is intentionally limited to:

- configured use case name
- success or failure outcome
- duration
- emitted event count
- executed workflow count

Do not put user data, request data, or secrets in the use case `name`.

## Configure Global Logging

Set global logging config once during application startup:

```kotlin
useCaseLoggingGlobalConfig {
  outcomeStyle(OutcomeStyle.Plain)
  defaultSummaryFields(DefaultSummaryFields.Enabled)
}
```

Options:

| Setting | Values | Default |
| --- | --- | --- |
| `outcomeStyle` | `OutcomeStyle.Plain`, `OutcomeStyle.AnsiColor` | `OutcomeStyle.Plain` |
| `defaultSummaryFields` | `DefaultSummaryFields.Enabled`, `DefaultSummaryFields.Disabled` | `DefaultSummaryFields.Enabled` |

`OutcomeStyle.AnsiColor` colors only the `outcome` value for local console logs. Log fields render as stable `key=value` pairs.

The examples below use this mapped public error type:

```kotlin
data class RegisterUserError(
  val reason: String,
  val retryable: Boolean,
)

fun toRegisterUserError(error: WorkflowError): RegisterUserError =
  when (error) {
    is WorkflowError.ValidationError ->
      RegisterUserError(reason = "validation", retryable = false)
    is WorkflowError.DomainError ->
      RegisterUserError(reason = error.code, retryable = false)
    else ->
      RegisterUserError(reason = "unexpected", retryable = true)
  }
```

## Add Success Fields

Use `success(state<T>())` when the field comes from the final workflow state:

```kotlin
val registerUser: UseCase<RegisterUserCommand, RegisterUserError, UserDto> =
  useCase(
    name = "RegisterUser",
    errors = ::toRegisterUserError,
  ) {
    startWith { command -> Either.Right(RegistrationDraft(command.email, command.password)) }
    then(CreateUserWorkflow(users))

    result(state<RegisteredUser>()) { state ->
      UserDto(id = state.id, email = state.email)
    }

    logging {
      success(state<RegisteredUser>()) { state ->
        field("userId", state.id)
      }
    }
  }
```

Use `success(event<T>())` when the field comes from the last emitted event of that type:

```kotlin
logging {
  success(event<UserRegisteredEvent>()) { event ->
    field("eventId", event.id)
  }
}
```

If the requested state or event is missing, the use case result is unchanged and the logging failure is reported separately.

## Add Failure Fields

Failure logging is typed to the use case error type.

If you preserve raw workflow errors, the failure value is `WorkflowError`:

```kotlin
val registerUser: UseCase<RegisterUserCommand, WorkflowError, UserDto> =
  useCase(name = "RegisterUser") {
    startWith { command -> Either.Right(RegistrationDraft(command.email, command.password)) }
    then(CreateUserWorkflow(users))
    result(state<RegisteredUser>()) { state -> UserDto(state.id, state.email) }

    logging {
      failure { error ->
        field("errorType", error::class.simpleName)
      }
    }
  }
```

If you map errors, the failure value is your mapped public error type:

```kotlin
val registerUser: UseCase<RegisterUserCommand, RegisterUserError, UserDto> =
  useCase(
    name = "RegisterUser",
    errors = ::toRegisterUserError,
  ) {
    startWith { command -> Either.Right(RegistrationDraft(command.email, command.password)) }
    then(CreateUserWorkflow(users))
    result(state<RegisteredUser>()) { state -> UserDto(state.id, state.email) }

    logging {
      failure { error ->
        field("reason", error.reason)
        field("retryable", error.retryable)
      }
    }
  }
```

The `errors = ...` mapper is still optional. Use it only when the public use case should return a non-`WorkflowError` error type.

## Field Naming

Choose stable field names for your logging and metrics systems:

```kotlin
field("userId", state.id)
field("retryable", error.retryable)
```

These built-in names are reserved and cannot be used for explicit fields:

- `name`
- `outcome`
- `durationMs`
- `events`
- `workflows`

Invalid field names or thrown logging lambdas are reported as logging projection failures. They do not change the use case result.

## Migrating UseCaseBuilder Helpers

Most users do not need to change their use-case definitions.

Only code that explicitly references `UseCaseBuilder<I, O>` needs to add the use case error type parameter:

Before:

```kotlin
fun UseCaseBuilder<RegisterUserCommand, UserDto>.withRegisterUserResult() {
  result(state<RegisteredUser>()) { state ->
    UserDto(state.id, state.email)
  }
}
```

After:

```kotlin
fun <E> UseCaseBuilder<RegisterUserCommand, E, UserDto>.withRegisterUserResult() {
  result(state<RegisteredUser>()) { state ->
    UserDto(state.id, state.email)
  }
}
```

If the helper configures failure logging for a mapped error type, use that specific error type:

```kotlin
fun UseCaseBuilder<RegisterUserCommand, RegisterUserError, UserDto>.withFailureLogging() {
  logging {
    failure { error ->
      field("reason", error.reason)
      field("retryable", error.retryable)
    }
  }
}
```
