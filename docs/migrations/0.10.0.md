# Migrating to v0.10.0

v0.10.0 is not released yet. This guide grows as each breaking change lands on `main`.

## Steps are functions

In 0.9.x, a step that needed its own class implemented `Workflow<I, O>` and overrode `suspend fun WorkflowStepScope.execute(input: I): O`. In 0.10.0, `Workflow` is a class the library builds, so you can't implement it. Write business logic as ordinary functions, and turn them into steps where the pipeline is assembled.

| 0.9.x | 0.10.0 |
| --- | --- |
| `class X(deps) : Workflow<I, O> { override val id = "x"; override suspend fun WorkflowStepScope.execute(input: I): O }` | A function on a service, called from `.then("x") { service.x(it) }` or `workflow<I, O, E>("x") { service.x(it) }` |
| `.then(X(deps))` | `.then("x") { state -> service.x(state) }` |
| `.then(guard("authorize") { ... })` | `.guard("authorize") { ... }` (top-level `guard` still exists for reusable checks) |
| `WorkflowExecution.workflowName` is the class name for class-based steps | `workflowName` is always the step `id` |

### Before

```kotlin
class CapturePayment(private val gateway: PaymentGateway) : Workflow<PricedOrder, PaidOrder> {
  override val id = "capture-payment"

  override suspend fun WorkflowStepScope.execute(input: PricedOrder): PaidOrder {
    val receipt = gateway.capture(input.total) ?: raise(OrderError.PaymentDeclined("card declined"))
    emit(PaymentCaptured(input.orderId, receipt.id))
    return PaidOrder(input, receipt)
  }
}

startWith { command -> OrderDraft(command.orderId, command.items) }
  .then(validateOrder)
  .then(CapturePayment(gateway))
```

### After

```kotlin
class Payments(private val gateway: PaymentGateway) {
  context(_: Raise<OrderError>)
  suspend fun capture(order: PricedOrder): PaidOrder {
    val receipt = gateway.capture(order.total) ?: raise(OrderError.PaymentDeclined("card declined"))
    return PaidOrder(order, receipt)
  }
}

startWith { command -> OrderDraft(command.orderId, command.items) }
  .then(validateOrder)
  .then("capture-payment") { order ->
    payments.capture(order).also { emit(PaymentCaptured(order.orderId, it.receipt.id)) }
  }
```

### Steps

- Move the body of `execute` into a function on a class that holds the dependencies. If it raises errors, declare `context(_: Raise<YourError>)` and import `ensure`/`ensureNotNull` from `arrow.core.raise.context`. A receiver, `suspend fun Raise<YourError>.capture(...)`, works too.
- Keep `emit` calls in the step block, where the `WorkflowStepScope` is available. A function that must emit can declare `context(step: WorkflowStepScope<YourError>)` instead.
- Replace `.then(X(deps))` with `.then("x") { x.run(it) }`. Kotlin doesn't allow method references to functions with context parameters, so use a lambda rather than `x::run`.
- Steps passed to `parallel`, `parallelJoin`, `thenIf` or `thenLaunch` still need to be values: define them with `workflow<I, O, E>("id") { ... }`. The error type `E` is covered in [Errors are your own types](#errors-are-your-own-types).
- Unit-test the domain function with Arrow alone (`either { payments.capture(order) }`), or call a `workflow` value directly as before.

## `Event` is a marker

`Event` no longer declares `id: UUID` and `timestamp: Instant`.

| 0.9.x | 0.10.0 |
| --- | --- |
| `data class OrderPlaced(override val id: UUID, override val timestamp: Instant, val orderId: String) : Event` | `data class OrderPlaced(val orderId: String) : Event`, or keep the fields without `override` |
| `class OrderPlaced(...) : BaseEvent()` | Unchanged. Pass `BaseEvent(id = ids.next(), timestamp = clock.instant())` to use your own clock or ID generator. |
| `LaunchedFailureEvent(id, timestamp, workflowId, message)` | `LaunchedFailureEvent(workflowId, message)` |
| `event.id` / `event.timestamp` on an `Event` | Available only on events that declare them, such as `BaseEvent` subclasses |

## The context is read-only

`WorkflowStepScope.put` is removed. `WorkflowContext` carries request metadata the caller supplies, such as a correlation ID or tenant, and steps can only read it. Data a step produces belongs in the state it returns, where the compiler checks every later step that uses it.

### Before

```kotlin
val checkInventory = workflow<PricedOrder, Unit>("check-inventory") { order ->
  put(Keys.INVENTORY_AVAILABLE, inventory.isAvailable(order))
}

.parallel(checkInventory, capturePayment)
.thenIf(prepareShipment) { context[Keys.INVENTORY_AVAILABLE] == true }
```

### After

```kotlin
data class PricedOrder(/* ... */, val inventoryAvailable: Boolean = false)

val checkInventory = workflow<PricedOrder, PricedOrder, Nothing>("check-inventory") { order ->
  order.copy(inventoryAvailable = inventory.isAvailable(order))
}

.then(checkInventory)
.parallel(capturePayment, notifyWarehouse)
.thenIf(prepareShipment) { order -> order.inventoryAvailable }
```

- Replace each `put(key, value)` with a field on the state the step returns.
- Steps that only ran in `parallel` to `put` a value become `.then` steps that return the enriched state, or one branch of a `parallelJoin`.
- Keep `WorkflowContext.of(...)` for what the caller passes in, and keep reading it with `context[key]`.

## `useCase` requires a name

`name` used to default to `"UseCase"`. It is now a required first parameter, so every log line and summary says which use case it came from.

| 0.9.x | 0.10.0 |
| --- | --- |
| `useCase { ... }` | `useCase("PlaceOrder") { ... }` |
| `useCase(errors = ::toApiError) { ... }` | `useCase("PlaceOrder", errors = ::toApiError) { ... }` |
| `useCase(name = "PlaceOrder", ...) { ... }` | Unchanged |

## Logging config is a value

`useCaseLoggingGlobalConfig { }` set process-wide mutable state. It is replaced by a `UseCaseConfig` value that you pass to each use case, like any other dependency.

### Before

```kotlin
// At startup
useCaseLoggingGlobalConfig {
  outcomeStyle(OutcomeStyle.AnsiColor)
  onSummary { summary -> metrics.record(summary) }
}

val placeOrder = useCase(name = "PlaceOrder", errors = ::toApiError) { ... }
```

### After

```kotlin
val appConfig = useCaseConfig {
  outcomeStyle(OutcomeStyle.AnsiColor)
  onSummary { summary -> metrics.record(summary) }
}

val placeOrder = useCase("PlaceOrder", errors = ::toApiError, config = appConfig) { ... }
```

- A use case built without `config` uses `UseCaseConfig.Default`: plain outcomes, default summary fields, and no listeners.
- `useCaseConfig(appConfig) { ... }` starts from an existing config, to adjust it for one use case.
- `clearSummaryListeners()` is removed. Build a new config instead.
- Tests no longer need to reset global state; give the use case under test its own config.

## Errors are your own types

`WorkflowError` and its built-in errors (`ValidationError`, `ExecutionError`, `DomainError`, `ExceptionError`, `CompositionError`) are removed. Each pipeline has one error type, chosen by you, and every step declares the error type it raises. The `errors` mapper receives a `Failure` of that type, so its `when` is exhaustive: adding an error case is a compile error until it is mapped.

| 0.9.x | 0.10.0 |
| --- | --- |
| `sealed interface OrderError : WorkflowError` | `sealed interface OrderError` |
| `Workflow<I, O>` | `Workflow<I, O, E>`; `Nothing` for a step that never raises |
| `workflow<I, O>("id") { }` | `workflow<I, O, E>("id") { }`; inline `.then("id") { }` needs no type arguments |
| `guard<I>("id") { }` | `guard<I, E>("id") { }` |
| `WorkflowStepScope` | `WorkflowStepScope<E>` |
| `errors: (WorkflowError) -> R` | `errors: (Failure<E>) -> R` |
| `UseCase<I, WorkflowError, O>` without `errors` | `UseCase<I, Failure<E>, O>` |
| `useCase<I, O>(...)` / `useCase<I, R, O>(...)` | `useCase<I, E, O>(...)` / `useCase<I, E, R, O>(...)` |
| `WorkflowError.ValidationError`, `DomainError`, `ExecutionError` | A case of your own error type |
| `WorkflowError.ExceptionError(message, ex)` | `Failure.Unexpected(cause)` |
| `WorkflowError.CompositionError` (missing `requireEvent`, `startWith` returned an `Either`) | `Failure.Unexpected` whose `cause` is a `WorkflowCompositionException` |
| `thenLaunch` timeout as `ExecutionError` | Still reported as a `LaunchedFailureEvent`; the message is unchanged |
| Steps with different error hierarchies mix freely | Adapt with `step.mapError { e -> MyError(e) }` |
| `ResultScope<S>`, a `Raise<WorkflowError>` | `ResultScope<S, E>`, a `Raise<E>` |
| `.logging { failure { error: R -> } }` gets the mapped error | `failure { failure: Failure<E> -> }` gets the failure before mapping |
| `RootErrorInfo(type, code, message, workflowId)` | `RootErrorInfo(type, unexpected, message, workflowId)` |
| `LaunchedFailureEvent.message` is the error's `message` | The raised error's class name, or `An exception occurred` |
| `WorkflowError.rootCause()` | Removed |

### Before

```kotlin
sealed interface OrderError : WorkflowError {
  data object EmptyOrder : OrderError
  data class PaymentDeclined(val reason: String) : OrderError
}

val validateOrder = workflow<OrderDraft, ValidatedOrder>("validate-order") { draft ->
  ensure(draft.items.isNotEmpty()) { OrderError.EmptyOrder }
  ValidatedOrder(draft.orderId, draft.items)
}

fun toApiError(error: WorkflowError): ApiError = when (error) {
  OrderError.EmptyOrder -> ApiError.BadRequest("Order has no items")
  is OrderError.PaymentDeclined -> ApiError.PaymentRequired(error.reason)
  is WorkflowError.ValidationError -> ApiError.BadRequest(error.message)
  else -> ApiError.Internal
}

val placeOrder = useCase(name = "PlaceOrder", errors = ::toApiError) {
  startWith { command: PlaceOrder ->
    ensure(command.id.isNotBlank()) { WorkflowError.ValidationError("id is required") }
    OrderDraft(command.id, command.items)
  }
    .then(validateOrder)
    .then("capture-payment") { order -> payments.capture(order) }
    .result { it.toDto() }
}
```

### After

```kotlin
sealed interface OrderError {
  data object MissingId : OrderError
  data object EmptyOrder : OrderError
  data class PaymentDeclined(val reason: String) : OrderError
}

val validateOrder = workflow<OrderDraft, ValidatedOrder, OrderError>("validate-order") { draft ->
  ensure(draft.items.isNotEmpty()) { OrderError.EmptyOrder }
  ValidatedOrder(draft.orderId, draft.items)
}

fun toApiError(failure: Failure<OrderError>): ApiError = when (failure) {
  is Failure.Raised -> when (val error = failure.error) {
    OrderError.MissingId -> ApiError.BadRequest("id is required")
    OrderError.EmptyOrder -> ApiError.BadRequest("Order has no items")
    is OrderError.PaymentDeclined -> ApiError.PaymentRequired(error.reason)
  }
  is Failure.Unexpected -> ApiError.Internal
}

val placeOrder = useCase(name = "PlaceOrder", errors = ::toApiError) {
  startWith { command: PlaceOrder ->
    ensure(command.id.isNotBlank()) { OrderError.MissingId }
    OrderDraft(command.id, command.items)
  }
    .then(validateOrder)
    .then("capture-payment") { order -> payments.capture(order) }
    .result { it.toDto() }
}
```

### Steps

- Remove `: WorkflowError` from your error types. Replace uses of the built-in errors with cases of your own type.
- Add the error type to each `workflow<I, O>` and `guard<I>` value. Use `Nothing` for steps that never raise.
- Rewrite the `errors` mapper to take `Failure<YourError>`, and drop its `else` branch.
- If a step raises a different error hierarchy, add `.mapError { ... }` where it joins the pipeline.
- Tests that expected `Either.Left(error)` from a step or use case without a mapper now expect `Either.Left(Failure.Raised(error))`.
