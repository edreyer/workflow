# Migrating v0.6.0 Typed Boundary Use Cases to v0.7.0 Use Cases

v0.7.0 replaces the v0.6.0 typed-boundary API with one primary `useCase` DSL.

The core model is:

- `UseCase<I, E, O>` is the public callable use case type.
- `useCase<I, E, O>(name = "...", errors = ...) { ... }` defines input, workflow steps, error mapping, and output projection in one place.
- `startWith { input -> ... }` replaces v0.6.0 `inputMapper` usage by converting public input directly into the initial workflow state.
- `errors = ...` replaces v0.6.0 `errorMapper` usage.
- `result(...)` replaces v0.6.0 `outputMapper` usage by projecting public output from the final state, an emitted event, or a custom projection.
- `TypedUseCase`, `ContextualTypedUseCase`, `toStateUseCase(...)`, and `toEventUseCase(...)` were removed to avoid a separate adapter layer.
- `WorkflowError` can be mapped to a boundary error type with `errors = ...`.
- The optional `name` is used for debug-level invocation logs. Keep it stable and free of user data.

## State Projection

Before:

```kotlin
val registerUser: ContextualTypedUseCase<RegisterUserCommand, ApplicationError, UserDto> =
  registerUserUseCase.toStateUseCase(
    inputMapper = ::RegisterUserWorkflowCommand,
    errorMapper = WorkflowError::toApplicationError,
    outputMapper = { state: RegisteredUserState -> state.user.toDto() },
  )
```

After:

```kotlin
val registerUser: UseCase<RegisterUserCommand, ApplicationError, UserDto> =
  useCase(
    name = "RegisterUser",
    errors = WorkflowError::toApplicationError,
  ) {
    startWith { command -> command.toValidatedState() }
    then(HashPasswordStep(passwordHasher))
    then(PersistUserStep(userRepository, userIdGenerator))
    result(state<RegisteredUserState>()) { state -> state.user.toDto() }
  }
```

## Event Projection

Before:

```kotlin
val registerUserEvent: ContextualTypedUseCase<RegisterUserCommand, ApplicationError, UserRegisteredEvent> =
  registerUserUseCase.toEventUseCase(
    inputMapper = ::RegisterUserWorkflowCommand,
    errorMapper = WorkflowError::toApplicationError,
    outputMapper = { event: UserRegisteredEvent -> event },
  )
```

After:

```kotlin
val registerUserEvent: UseCase<RegisterUserCommand, ApplicationError, UserRegisteredEvent> =
  useCase(
    name = "RegisterUser",
    errors = WorkflowError::toApplicationError,
  ) {
    startWith { command -> command.toValidatedState() }
    then(HashPasswordStep(passwordHasher))
    then(PersistUserStep(userRepository, userIdGenerator))
    result(event<UserRegisteredEvent>()) { event -> event }
  }
```

## Raw Workflow Errors

Omit `errors = ...` only when the use case's error type is `WorkflowError`.

```kotlin
val registerUser: UseCase<RegisterUserCommand, WorkflowError, UserDto> =
  useCase(name = "RegisterUser") {
    startWith { command -> command.toValidatedState() }
    then(HashPasswordStep(passwordHasher))
    then(PersistUserStep(userRepository, userIdGenerator))
    result(state<RegisteredUserState>()) { state -> state.user.toDto() }
  }
```

## Lower-Level WorkflowUseCase

The workflow-native execution model was renamed to `WorkflowUseCase`. Most application code should use callable `UseCase<I, E, O>` instead.

If you used the old lower-level `useCase { ... }` DSL and still need workflow-native execution methods such as `executeDetailed(...)`, rename that composition entry point to `workflowUseCase { ... }`.

```kotlin
val registerUserWorkflow: WorkflowUseCase<RegisterUserCommand> =
  workflowUseCase(name = "RegisterUser") {
    startWith { command -> command.toValidatedState() }
    then(HashPasswordStep(passwordHasher))
    then(PersistUserStep(userRepository, userIdGenerator))
  }
```

If you directly subclassed the old workflow-native `UseCase`, migrate to `WorkflowUseCase`.

Before:

```kotlin
class RegisterUserUseCase : UseCase<RegisterUserCommand>() {
  override suspend fun execute(command: RegisterUserCommand): Either<WorkflowError, UseCaseEvents> {
    // Custom implementation
  }
}
```

After:

```kotlin
class RegisterUserWorkflowUseCase : WorkflowUseCase<RegisterUserCommand>("RegisterUser") {
  protected override suspend fun executeUseCase(
    command: RegisterUserCommand,
    context: WorkflowContext
  ): Either<WorkflowError, UseCaseResult<WorkflowState>> {
    // Custom implementation
  }
}
```

## Invocation

Use cases are invoked directly:

```kotlin
val result = registerUser(command)
```

If the boundary has request metadata, pass an initial `WorkflowContext`:

```kotlin
val result =
  registerUser(
    command,
    WorkflowContext().addData(WorkflowContext.CORRELATION_ID, correlationId),
  )
```
